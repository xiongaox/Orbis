# Orbis 全端适配与优化规范

本技能定义了桌面端、Pad端和移动端适配任务的安全边界和工作流程。核心原则是：**对某一端的优化，必须且只能影响该端，绝不能干涉另外两端的现有布局和行为。**

---

## 1. 触发词与目标定义

当对话中出现以下触发词时，必须严格执行本规范：

| 触发词 | 目标平台 | 核心控制变量/逻辑 |
| :--- | :--- | :--- |
| **桌面端优化** | 桌面端 (Desktop) | `useDesktopLayout = isDesktop && !isPadLandscape` 为 `true` 的分支 |
| **Pad端优化** | Pad 横屏 (Pad Landscape) | `isPadLandscape` 为 `true` 的分支 |
| **移动端优化** | 移动端 (Mobile) | 排除上述两者后的默认分支（通常包含手机和 Pad 竖屏） |

---

## 2. 核心隔离准则（强制）

### 2.1 条件分支绝对隔离
禁止在未受端控变量保护的情况下修改基础类名或共享逻辑。

```tsx
// ✅ 正确：各端代码完全独立，互不拆分共享部分
{useDesktopLayout ? (
    <DesktopView /> // 桌面端优化仅在此修改
) : isPadLandscape ? (
    <PadView />     // Pad 端优化仅在此修改
) : (
    <MobileView />  // 移动端优化仅在此修改
)}
```

### 2.2 样式修改规范
- **禁止修改无前缀的基础类名**（如 `flex`, `p-4`, `bg-card`），除非确定该修改在所有端都适用。
- **优先使用响应式前缀**：
    - `lg:` 仅用于桌面端优化（配合 `useDesktopLayout`）。
    - 针对 Pad 和移动端的差异，必须使用 `isPadLandscape` 进行逻辑判断，而非单纯依赖 CSS 媒体查询。

### 2.3 共享状态保护
当修改共享状态（如 `useState`, `props`）时：
1. **全量搜索**：使用 `grep_search` 查找该变量的所有引用。
2. **端保护**：在每个引用点检查是否需要按端区分行为。
3. **独立化**：如果逻辑冲突，优先为特定端创建独立的状态变量（如 `isPadSettingsOpen`）。

---

## 3. 工作流程

1. **环境确认**：确认项目根目录为 `Orbis`。
2. **意图识别**：识别用户请求的是哪一端的优化，并在回复开头明确声明：“[技能启动] 正在进行 <端名称> 优化，确保不影响其他端布局。”
3. **代码实施**：
   - 仅在对应端的代码块/条件分支内进行修改。
   - 如果需要修改公共组件，必须增加可选 Props 或在组件内部通过布局变量进行分支处理。
4. **回归检查**：
   - 检查是否误删或误改了非目标端的条件分支。
   - 验证三元表达式或逻辑判断的完整性。

---

## 4. 验证清单（提交前必选）

- [ ] **端隔离验证**：确认改动点是否被 `useDesktopLayout`, `isPadLandscape` 或对应的三元表达式包裹。
- [ ] **视觉回归**：
    - [ ] 桌面端（1440×900）无布局偏移或功能缺失。
    - [ ] Pad 横屏（1024×768）交互正常。
    - [ ] 移动端（375×812）优化生效。
- [ ] **代码清洁度**：未修改无端控保护的基础样式类。

---

## 5. 错误回退

**若发现一端优化导致另一端“变样”或功能异常：**
1. 立即回退受影响的文件。
2. 重新分析 `QimenPage.tsx` 等页面布局容器的入口逻辑。
3. 确保所有改动严格锁定在目标端的 `if/else` 或 `? :` 分支内。
