侧栏案例列表 · 重排四稿

因案例库独立界面重构，侧栏案例列表需按新的卡片元素重新排版。 硬约束：宽度不变 —— 桌面侧栏恒为 w-56 = 224px（2xl 断点 w-64 = 256px）， 下面四稿全部按 224px 真实宽度渲染，均为可交互 demo。

  • 为什么必须重排：现状卡（CaseCard.tsx）在 224px 里实测有两个硬伤 —— ① 四柱用 text-[19px] + w-6 柱宽，四列占 78px，把左侧文字挤到只剩 100px； ② 「编辑/删除」在触屏上因 hover 粘滞而常驻，卡高被顶到约 96px。
  • 四稿共同处理：编辑/删除改为左滑露出（排序模式下自动禁用）；分类 chip 与姓名同行；日期行不再塞 4 项； 仅日干取五行色，其余干支压暗；保留 乾/坤 印章与搜索/筛选/排序模式原有交互。
  • 取舍核心：224px 里「文字」与「四柱」是零和的。四稿给出四种分法 —— 文字优先（A）、排盘优先（B）、两列均分（C）、高度优先（D）。
  • 自验方式：每稿都用脚本量测真实盒模型（侧栏宽度、横向溢出、文字是否撑破盒子）并驱动鼠标跑完 8 项交互测试，四稿均 100% 通过；不是只靠肉眼截图。

方案 A文字优先

卡高 53px · 干支 14px 竖排 · 含时辰 否
最贴近现状的结构，只做瘦身：仍是「左资料 / 右四柱」。四柱压到 16px 柱宽，把省下的宽度全给文字， 第二行只留 日期 + 年龄，分类上移到姓名右侧。改动最小、迁移成本最低； 代价是删掉了出生时辰（整页案例库仍有完整信息）。

方案 B排盘主导

卡高 103px · 干支 18px 竖排 · 含时辰 否
领域感最强：排盘是卡片主角，居中放大到 18px，并加一行极淡的 年/月/日/时 柱名做参照系； 姓名与日期压成上下两行细字。干支可读性四稿最好，格局派扫一眼就能定位日主； 代价是卡高翻倍（约 103px），一屏可见条数明显减少。

方案 C两列均分

卡高 62px · 干支 14px 竖排 · 含时辰 否
用 grid 两列把 224px 明确切开：左列姓名+日期，右列排盘+年龄。 年龄做成主色小字角标钉在排盘右下，成为扫读锚点；分类 chip 推在第一行最右。 密度与可读性折中，版面最「整齐」；代价是左侧文字列最窄，长名省略更早。

方案 D高度最优

卡高 70px · 干支 14px 横排 · 含时辰 是
把「干上支下」压成干支一组横排（乙巳 己丑 丁亥 庚戌），与案例库整页的写法一致。 干支自成一段、不再与文字争宽度，因此唯一保留了出生时辰；日柱整组加淡主色底做锚点。 代价是失去列对齐，日干高亮不如竖排醒目。
